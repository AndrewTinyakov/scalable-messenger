# Presence load benchmark, 27 November 2026

At 3,500 quiet sockets, gateway-owned presence cut application traffic from 1,397.1 frames/s to zero and Redis commands from 44,260/s to 444/s. It passed every capacity stage up to 15,000 sockets; legacy stopped at 4,000. It stayed up through a Redis primary outage with no gateway exits, where legacy gateways crashed four times. [Charts](results-2026-11-27.html)

The current build was measured twice. The first run found a gateway crash on Redis loss and a scoring flaw in this driver. Both are fixed, and the current build was run again at `566e401`. Legacy churn was run again under the new scoring. The other legacy rows come from the first run.

## Method

Both Compose projects ran on the same Apple M3 Pro with 11 logical CPUs and 36 GiB RAM. OrbStack had 11 CPUs and 15.7 GiB RAM. The driver ran on Node 24.21.0. Each project had two gateways, two APIs and a Redis 7.4.11 cluster with three primaries and three replicas. Scenarios ran one at a time with a 60-second pause between them. The rerun of the current build and legacy churn took 1 hour 21 minutes.

Legacy ran the gateway image tagged `e56bc28`. The current gateway and outbox publisher ran images built at `566e401`, and the driver was the one at `566e401`. Later commits changed only the handling of rare races and of the Redis settings, plus edge cases in the driver's scoring.

Both stacks used the same seeded plan: 16,384 users, 414,547 direct chats and 256 groups, seed 1118, one device per user. Tickets were fetched before any timed window, and sockets opened at up to 100/s. Timed windows exercised presence only, with no chat messages. Both protocols used the same watch sets. Prometheus rates are means over each window. Redis commands include shared room and session traffic. The driver stayed under its 50 ms event-loop p99 limit in every window.

A delivery counts on time only if it arrives within 15 seconds (or within the hold after a gateway kill) and its watcher stays connected until then. Watchers that close first are reported separately and left out of the score. In the first run they counted against the on-time share. Under clustered churn, many watchers leave during the current build's intended 2-second offline grace, so the first run showed 37.1% on time against legacy's 75.8% even though neither build had a late or missing delivery.

## Gateway kill

Killing one gateway displaced 800 sockets on each build. The surviving gateway's watchers saw them go offline with p99 of 12.5 seconds on current and 94.9 seconds on legacy, all on time within the 150-second hold. All 800 then reconnected and became ready, in 17.0 seconds on current and 20.0 on legacy, including the reconnect ramp.

## Redis primary kill

| During the 120-second outage | Legacy, first run | Current, first run | Current, rerun |
| --- | ---: | ---: | ---: |
| Gateway process exits | 4 | 1 | 0 |
| Abnormal WebSocket closes | 1,917 | 1,396 | 526 |
| Failed upgrades, HTTP 502 / 503 / 429 | 547 / 840 / 155 | 2,553 / 3 / 0 | 1,357 / 3 / 0 |
| Offline deliveries late / missing | 49 / 493 | 5 / 13 | 0 / 0 |
| Ready / intended at the outage cutoff | 1,579 / 1,580 | 1,579 / 1,580 | 1,579 / 1,580 |

In the first run, gateways on both builds exited with code 2 when a Redis room subscription failed. The adapter returned a nil `*Listener` inside a non-nil interface, and the error path called `Close` on it. The fix returns a nil interface, here and in the presence feed adapter, and a regression test covers it. In the rerun, neither current gateway restarted or logged a panic. The gateway metrics also recorded 526 stale-room events, where the gateway drops connections whose room lost its Redis subscription; the metrics don't pair events with sockets.

Changes that started during the outage were delivered offline with p50 / p90 / p99 of 2,193 / 2,196 / 9,871 ms and online with p99 of 197 ms, all on time. Changes are counted in the phase where they start; those started just before the kill had 5 late offline and 96 late online deliveries. Both clusters promoted a replica. `redis-2` rejoined as a replica, and the runner's `CLUSTER FAILOVER` made it primary again for slots 5461–10922. Both stacks finished with both gateways healthy, six Redis nodes and `cluster_state:ok`.

Raw reports, exit logs, Docker events and the recomputation script stayed on the benchmark host under `/tmp/presence-load/`.
