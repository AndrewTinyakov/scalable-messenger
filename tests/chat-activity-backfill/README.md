Run `tests/chat-activity-backfill/run.sh` from the repository root with Docker available. It creates and removes its own PostgreSQL 19 container, limited to two CPUs and 768 MiB. It seeds 1,192,660 messages in 5,201 chats, clears activity, and runs the production backfill. The final NOTICE reports the longest batch including commit, an upper bound on each batch's chat lock duration. Waiting for competing transactions can increase that duration.

V10 only adds the nullable column. V11 disables Flyway's enclosing transaction and commits every 5,000 message rows, using the message primary key and a captured upper bound. Each update keeps the larger stored activity. Readers retain their membership-time fallback until a chat is backfilled. If interrupted, Flyway repair followed by migrate safely repeats already committed batches; do not mark the failed migration successful. The procedure is replaced on retry and removed after success.

The normal API test `ChatActivityMigrationTests` runs the actual Flyway migrations against Testcontainers PostgreSQL. It holds a second-batch chat lock, observes the first batch's committed result from another connection, commits newer send activity, and checks the backfill preserves it. The benchmark is an explicit shell command and never runs with the default tests.
