# Personal chat state, message pins and forwards

Status: accepted.

Chat pins, mutes and unread marks live as nullable columns on the account's `chat_members` row: `pinned_rank`, `muted_until` and `marked_unread_at`. PostgreSQL stores no bytes for a null value beyond the existing null bitmap, so accounts that never use these features add no row width. A partial index over `(user_id, pinned_rank)` covers only pinned rows. A permanent mute stores `infinity`; reads treat a past end time as unmuted, so mutes need no expiry job. Chat pin changes take a per-account advisory lock and rewrite at most ten ranks. Directory pages put pinned chats first on the uncursored page and exclude them from activity keysets, so pagination stays a single index-ordered scan.

Message pins use one narrow table `(chat_id, sequence, viewer_id)`. A null viewer means the pin is shared with every member; a viewer ID means a personal pin, which only direct chats accept. A `NULLS NOT DISTINCT` unique constraint makes pinning idempotent. The foreign key to `messages(chat_id, sequence)` cascades, so global deletion and purge remove pins without tombstones. Personal deletion and clear-history hide pins through the existing visibility predicate. A per-chat advisory lock serialises the 200-pin scope cap. List pages are newest-first keysets over at most 400 rows per viewer.

Every change commits one bodyless outbox hint in the same transaction. Personal chat state emits `chat_preferences_changed` to the account's user room only. Shared group pins emit `pins_changed` to the group room, shared direct pins to both user rooms, and personal pins to the owner's user room. These hints carry no message content and reuse the room publication, replay and deduplication rules from ADR 0001; clients refetch authoritative state, and periodic refresh repairs missed hints.

A forward is a normal send command with `forwardFromChatId` and `forwardFromMessageId`. It reuses RabbitMQ partitioning, request-ID deduplication and the send transaction. The processor copies the source body visible to the sender inside that transaction and records `forwarded_from_user_id`. Forwarding a forward credits the original author. The client's body only renders the pending bubble. A source that is missing or hidden from the sender rejects with `INVALID_FORWARD_SOURCE`. The copied row is independent: deleting the source does not delete the forward.

Notifications are computed on the client from authoritative summary changes, the account's mute state and local sound and desktop preferences. Direct chats reach every device through user rooms. Groups reach devices through sidebar hints for watched rows and the periodic directory refresh, so an alert for an unwatched group can wait for that refresh.
